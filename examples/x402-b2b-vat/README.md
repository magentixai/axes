# x402 B2B VAT worked example (WO20)

One x402 payment between two businesses, with the identity, tax and evidence lanes offered and chosen, both parties keeping their own AXES record, and each record anchored independently. Generated by `tools/x402/generate_b2b_vat_example.py`; checked in CI on Linux, macOS and Windows.

## The flow on one page

1. **Offer.** The seller answers `402` with `x402-wire/payment_required.json`. Plain x402 v2, `exact` scheme, Base Sepolia (`eip155:84532`), 0.01 test USDC, plus three optional lanes in `extensions`:
   - `identity`: who the supplier is;
   - `tax`: the quoted EU VAT result;
   - `evidence`: the correlation recipe and a server salt.
2. **Authorization.** The buyer signs an EIP-3009 authorization (real EIP-712 signature, test key) and retries with `x402-wire/payment_payload.json`. It echoes every lane unchanged and appends its choices: the business-buyer disclosure, the PR #5 tax declaration, and its own salt.
3. **Correlation.** Each party computes `correlation_hash` on its own (`tools/x402/x402_correlation.py`) from bytes both hold at that moment. Result: `correlation/correlation.json`. Nothing about the evidence travels in x402 except references and the salts.
4. **Records.** Buyer and seller each keep an AXES record (`buyer/envelopes.jsonl`, `seller/envelopes.jsonl`) covering offer, tax, authorization, settlement, receipt and anchoring. Every envelope carries the same `correlation_hash` and is signed by that party's emitter key.
5. **Anchors.** Each party anchored the chain head of its first five envelopes, in a public GitHub Actions run:
   - an RFC 3161 time stamp (FreeTSA), verified;
   - OpenTimestamps on Bitcoin, pending until the scheduled upgrade.

   See `anchors/x402-b2b-vat-buyer/` and `anchors/x402-b2b-vat-seller/`. The sixth envelope records the anchoring block.
6. **Receipt.** `x402-wire/receipt_v1.json` is today's privacy-minimal receipt. `x402-wire/receipt_v2.json` is the proposed version 2, which carries `correlationDigest` so the seller cannot later disown which payment and lane choices the receipt belongs to.
7. **Evaluation.** `evaluations/` holds the result of applying the WO20 requirement profiles with the reference evaluator (`tools/axes_evaluate.py` on `golden-trace-v2`).

The same payment under an x402#3220 spending mandate is `x402-wire/payment_payload_mandate_bound.json`. Its nonce is the mandate binding `B`, so the correlation hash already commits to the mandate. `correlation/correlation_mandate_bound.json` records `nonce_derivation_type: x402_mandate_binding`, recomputed rather than asserted.

## What is real and what is not

| Element | Status | Why |
|---|---|---|
| EIP-3009 authorization signature | real (test key) | EIP-712 over the USDC Base Sepolia domain. The keys derive from public seeds in the generator: never fund them |
| Envelope signatures | real (test keys) | `envelope_signature_basis_status: demonstrated` |
| RFC 3161 anchors | real | FreeTSA, verifiable offline with `tools/anchoring/verify_anchor.py` |
| OpenTimestamps anchors | real, pending | Upgraded to a Bitcoin attestation by the scheduled anchor workflow |
| Settlement | **simulated** | No testnet access from the generating environment. `settled_artifact_basis_status: simulated` with the reason. The x402.magentix.ai test bed replaces it with a decoded Base Sepolia settlement |
| Receipt signatures | **stubbed** | The offer-and-receipt signing format is aligned at the pinned x402 commit before this example claims it |
| Facilitator address | placeholder | Replaced by the real facilitator when the settlement is real |

Because the settlement is simulated, every evaluation is honestly `indeterminate`, on exactly one requirement: `x402_settled_basis_01` / `basis_not_demonstrated`. Everything else verifies:
- chain integrity;
- the correlation hash on every envelope;
- decode-and-compare between the committed terms and the (simulated) settled artifact;
- supplier identity;
- tax result and principal attribution;
- one demonstrated anchor per party.

When the test bed supplies a real settlement, that requirement is the only one that changes.

## Reproduce

```bash
python tools/x402/x402_correlation.py examples/x402-b2b-vat/x402-wire/payment_required.json examples/x402-b2b-vat/x402-wire/payment_payload.json
python tools/x402/test_x402_correlation.py
python tools/anchoring/verify_anchor.py anchors/x402-b2b-vat-buyer --subject anchors/x402-b2b-vat-buyer/bundle_manifest.json
```

**ARBITR** is the implementer of this run's design (the reference Tier 3 example). Nothing here requires ARBITR: any emitter that follows the recipe, the lane schemas (`schema/x402-wire/`) and the profiles (`profiles/x402_*`) reproduces the records from the published inputs. A second, independent emitter reproducing this example is welcome.
